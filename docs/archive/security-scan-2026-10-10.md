# GitHub Actions security scan evidence — 2026-10-10

- Third-party `uses:` references in `.github/workflows/` and `.github/actions/` were inspected; all are pinned to full commit SHAs with version comments. The only non-SHA `uses:` references are local composite action references (`./.github/actions/setup-builder`).
- A targeted source scan found no direct `${{ github.event.* }}` values interpolated into `run:` script bodies. Workflow-dispatch package names, build mode, make jobs and boolean controls are passed through environment variables or typed expressions; shell code uses quoted environment variables.
- `zizmor` v1.30.1 was downloaded to the workspace cache, checksum-verified, and run against `.github/workflows/*.yml` and `.github/actions/setup-builder/action.yml` with the authenticated GitHub API token. Result: 38 findings total, 33 suppressed by existing policy, 5 low-severity `self-repository` suggestions, and 0 medium/high findings. The five suggestions are now addressed by GitHub's `$/` self-repository syntax, which pins the local composite action to the exact workflow commit rather than a mutable workspace-relative checkout.
- Current `actionlint` does not yet recognize the GitHub `$/` syntax (upstream issue https://github.com/rhysd/actionlint/issues/711). `.github/actionlint.yaml` suppresses only the exact “action ... invalid format because ref is missing” diagnostic for that syntax; all other actionlint checks remain enabled. This is a linter compatibility exception, not a security suppression. Third-party actions remain pinned to full commit SHAs with version comments.
- Workflow hardening now scopes write permissions to jobs that need them, passes resolved image identifiers through environment variables instead of interpolating them into shell source, disables checkout credential persistence, and supplies explicit command-scoped token auth only for jobs that push commits. `actionlint`, ShellCheck, the fast suite and static checks were rerun after the changes.
